# Deploying HMS to a VPS (Ubuntu 22.04/24.04)

Stack: Nginx (reverse proxy + static/media) → Gunicorn (systemd service) → Django →
Postgres. Config templates for the pieces below live in this `deploy/` folder.

## 0. Prerequisites

- A VPS (DigitalOcean, Hetzner, AWS Lightsail, Hostinger VPS, etc.) running Ubuntu, with
  root/sudo SSH access.
- (Recommended) a domain name pointed at the server's IP (A record). You can deploy on
  the bare IP first and add the domain later.

## 1. Server setup

SSH in as root, then:

```bash
apt update && apt upgrade -y
adduser deploy                      # non-root user to run the app
usermod -aG sudo deploy
apt install -y python3-venv python3-pip nginx postgresql postgresql-contrib \
    libpq-dev git ufw

ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw enable
```

Log back in as `deploy` for everything after this.

## 2. Database

SQLite (the current default) will lock up under concurrent writes from 4 portals
(patient/doctor/receptionist/admin) hitting it at once — use Postgres, which
`requirements.txt` is already set up for via `psycopg2-binary` + `dj-database-url`.

```bash
sudo -u postgres psql -c "CREATE DATABASE hms;"
sudo -u postgres psql -c "CREATE USER hms_user WITH PASSWORD 'CHANGE_ME';"
sudo -u postgres psql -c "ALTER ROLE hms_user SET client_encoding TO 'utf8';"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE hms TO hms_user;"
```

## 3. Get the code and install dependencies

```bash
cd /home/deploy
git clone https://github.com/lakshitbuilds/Hospital-Management-System.git
cd Hospital-Management-System
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## 4. Configure `.env`

`config/settings.py` already reads everything below via `python-decouple` — see
`.env.example` for the email keys. Create `/home/deploy/Hospital-Management-System/.env`:

```
SECRET_KEY=<generate a new one, don't reuse the dev default>
DEBUG=False
ALLOWED_HOSTS=<your_domain>,<your_server_ip>
DATABASE_URL=postgres://hms_user:CHANGE_ME@localhost:5432/hms

EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=your-gmail-address@gmail.com
EMAIL_HOST_PASSWORD=your-16-char-app-password
DEFAULT_FROM_EMAIL=your-gmail-address@gmail.com
```

Generate a fresh `SECRET_KEY` with:
```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

## 5. Migrate and collect static files

```bash
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py createsuperuser   # or run seed_admin.py if that's how admin accounts are made
```

## 6. Gunicorn as a systemd service

Edit `deploy/gunicorn.service`, replacing `<DEPLOY_USER>` and `<PROJECT_PATH>`
(e.g. `/home/deploy/Hospital-Management-System`), then:

```bash
sudo cp deploy/gunicorn.service /etc/systemd/system/hms-gunicorn.service
sudo systemctl daemon-reload
sudo systemctl enable --now hms-gunicorn
sudo systemctl status hms-gunicorn   # confirm it's active and the socket file was created
```

## 7. Nginx

Edit `deploy/nginx.conf`, replacing `<YOUR_DOMAIN_OR_IP>` and `<PROJECT_PATH>`, then:

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/hms
sudo ln -s /etc/nginx/sites-available/hms /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

Also make sure `www-data` (Nginx's user) can traverse into your project directory:
```bash
sudo usermod -aG deploy www-data
chmod 750 /home/deploy
```

At this point the site should be reachable at `http://<your_domain_or_ip>`.

## 8. HTTPS (only works once a domain is pointed at the server)

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d <your_domain>
```
Certbot edits the Nginx config to add the SSL block and sets up auto-renewal.

## 9. Deploying future changes

```bash
cd /home/deploy/Hospital-Management-System
git pull
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
sudo systemctl restart hms-gunicorn
```

## Notes specific to this project

- Known blocker from an earlier session: Gmail SMTP auth was failing (`535 Username and
  Password not accepted`) because the app password didn't match Google's 16-char format.
  Regenerate it at https://myaccount.google.com/apppasswords and put it straight in
  `.env` on the server (never in chat, never committed).
- `media/` holds user-uploaded files (profile pictures) and is gitignored — it starts
  empty on a fresh server. `staticfiles/` is regenerated by `collectstatic`, don't
  commit it either.
